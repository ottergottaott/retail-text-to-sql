Architecture

One backend owns analysis, access and reports. WebUI and CLI use the same HTTP API.

Request path

Identity & scope → permitted context → typed model decision → validated SQL → query evidence → grounding review → answer / save.

LangGraph bounds calls, time and queries. One repair is allowed for repairable SQL errors.

Access and privacy

  • Brand managers see their brands; the CEO sees all brands.
  • Database PII columns are excluded from analytical sources; customer IDs are hashed. Demographics are aggregate-only; minimum cohort defaults to 5.
  • SQL AST validation, scoped sources and execution budgets run in trusted code.

Knowledge and state

Golden Trios supply methodology through lexical/vector retrieval. Publication validates SQL and rejects email/phone/IP patterns. Retrieval filters version, schema and access, then scans copies of the question, SQL and report. Embedding and generation payloads receive a local English PERSON scan plus value/field rules. Stored originals remain unchanged; old embedding keys are invalidated.

PostgreSQL stores conversations, owner-scoped reports and preferences. Report deletion requires explicit user confirmation.

Deployment

Docker Compose: API, PostgreSQL and Open WebUI. External services: Gemini and BigQuery, using reviewer-supplied credentials.

SQLite/DuckDB support synthetic offline tests. Langfuse is optional and disabled by default.

Prototype limits: static four-table schema; bounded personal preference learning has focused local test coverage; live acceptance remains pending; automatic shared-knowledge/tone promotion and durable mid-turn recovery remain design work. Local English NER and value/field rules protect outbound copies; detector failure blocks calls. Recognition can miss unusual or obfuscated PII and overmask safe text; arbitrary-prose privacy is not proven. WebUI stores original input before sanitization; do not enter real PII. Current client-policy changes await live acceptance.
